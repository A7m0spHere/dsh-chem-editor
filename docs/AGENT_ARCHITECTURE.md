# Agent 编辑能力与融合架构

日期：2026-10-08，状态更新于 2026-10-24。A0 模块整理及回归验收已完成；A1 草稿原型、A2 动态片段已实现并通过单元与浏览器确定性验收（含引擎探针），证据见 [A1 草稿验收](./A1_ACCEPTANCE.md) 与 [A2 动态片段验收](./A2_ACCEPTANCE.md)；各阶段真实官方 Web Agent 与 Desktop 原生验收按项目决定并入总验收，完成前不声明相应链路已验证；A3–A4 尚未实施。A0 的具体改动与证据见 [架构整理验收](./A0_ACCEPTANCE.md)。

本文是 Agent 能力融合、模块边界和迁移顺序的唯一规划入口。[开发方案](../DEVELOPMENT_PLAN.md)记录产品基线与已有能力，验收文件记录实际验证结果。实现后更新本文阶段状态和对应验收记录，不另外维护一份竞争的架构方案。

## 1. 方向与取舍

目标是让当前 DSH 会话中的 Agent 能分析分子、构造任意受支持的局部片段、连续修订候选结构，最后交给用户核对和应用。画布继续作为主工作区，DSH 原生助手按需展开。

自由度增加在“能表达哪些结构、能组合哪些步骤、能怎样读取反馈”上；编辑范围、版本、用户真实要求和应用事务仍由项目执行器负责。

确定采用：

- 单一 TypeScript 插件包，继续使用 DSH 当前会话的模型和工具循环。
- KET 是文档事实来源；SMILES/SMARTS 用于片段输入、交换和查询，不承担文档、坐标及原子身份。
- 增加宿主管理的编辑草稿会话，支持多轮操作和新建目标引用；画布只在用户应用时变化。
- 化学执行和结构范围验证只有一套共享实现；旧工具通过兼容适配进入同一核心。
- 默认化学能力继续来自已锁定的 Ketcher 3.7.0 / Indigo WASM；新增能力必须经过适配器探针。

第一轮不引入第二套 Agent 框架、Python 必需运行时、独立服务、多文档调度或多 Agent 编排。RDKit 与 MCP 是确有能力缺口时的可选接入方式，不成为基础编辑的前置条件。

## 2. 当前实现与需要解决的问题

| 当前模块 | 已承担的工作 | 迁移重点 |
| --- | --- | --- |
| `src/index.ts` | DSH 工具、HTTP/RPC 路由、资源服务、宿主装配 | 保留入口，分离工具 schema、桥接与服务装配 |
| `src/annotation-service.ts` | 批注状态、存档、冻结版本、提示词、提案、应用 | 保留批注语义，将草稿迭代和提示构建移出 |
| `src/molecular-patch.ts` | 操作归一化、KET 修改、边界/属性检查、步骤映射 | 分离图模型、执行与检查；为新步骤提供显式身份映射 |
| `src/edit-intent.ts` | 用正则核对操作、目标和完整步数 | 保留已知明确意图的防替换能力，逐步支持结构化目标合同 |
| `src/editor.tsx` | UI、快照映射、Indigo 检查、预览、历史、桥接 | 先抽出 KetcherAdapter 与桥接，再按组件职责拆 UI |
| `src/client.tsx` | DSH 布局、iframe 承载、草稿补存与面板切换 | 保留承载职责，不加入化学业务 |
| `src/document-store.ts` | 版本令牌、原子保存、应用回执 | 继续作为文档持久化入口 |
| `src/fragments.ts` / `fragment-layout.ts` | 固定片段、别名、局部布局 | 固定模板与动态片段统一归一化；保留局部布局规则 |

当前只有五类基础操作和九种片段；批量操作限 2–8 步，目标来自原冻结选区。已有预览不能直接修订；化学检查失败后会结束当前提案状态。扩大提示词或枚举表只能缓解个别案例。

当前批量步骤还使用坐标匹配重建部分原子身份。草稿编辑会引入更多新建、删除和局部布局操作，必须先建立显式映射，不能继续以坐标、SMILES 顺序或数组位置推断身份。

## 3. 分层与依赖

```text
DSH Agent / 原生聊天                 分子工作区 UI
         │                                │
  host/tools + prompt              client bridge + KetcherAdapter
         │                                │
         └──── host 编辑会话服务 ───────────┘
                       │
          contracts + chemistry 共享核心
                       │
           化学能力端口 / 浏览器 Indigo 实现
                       │
             可选查询、RDKit、MCP 适配器
```

宿主和浏览器各自调用共享核心；化学能力端口通过桥接调用浏览器实现。上图表示逻辑职责，不表示 Node 宿主直接加载浏览器 WASM。KetcherAdapter 负责实际画布实例、序列化映射和历史操作；化学适配器负责解析、布局与诊断，两者不能代替宿主决定提交。

| 层 | 拥有的职责 | 依赖约束 |
| --- | --- | --- |
| `contracts` | 文档、引用、草稿、操作、诊断、能力与桥接合同 | 不依赖 React、DSH、Ketcher、Node 文件系统 |
| `chemistry` | 归一化图、执行局部操作、影响范围、片段注册、完整计划检查 | 依赖合同；通过端口请求引擎能力，不导入 UI 或宿主服务 |
| `host` | 会话归属、串行化、批注/草稿状态、版本、幂等、提案、保存 | 依赖合同和核心；不访问 Ketcher 内部对象 |
| `adapters/ketcher` | 快照和身份映射、画布应用、手工/AI 统一撤销 | 依赖合同和 Ketcher；不注册 DSH 工具或保存磁盘文档 |
| `adapters/indigo` | 片段解析、局部坐标、已验证的结构检查和诊断 | 依赖合同与本地引擎；不持有批注状态或写文档 |
| `ui` / `client` | 展示、用户输入、工作区布局、生命周期与通信 | 调用服务/适配器；不实现第二份图修改规则 |
| 可选适配器 | 查询、描述符或默认引擎缺少的搜索能力 | 返回合同定义的结果；不直接覆盖文档 |

只定义已有使用方需要的端口，不预建通用插件市场、事件总线或服务容器。能力清单由实际可用的适配器生成，工具说明与界面读取同一清单。

## 4. 核心数据合同

以下是目标设计，不是已存在的工具/API。新增合同使用独立的 `protocolVersion: 2`；已有文档 `schemaVersion: 1` 第一阶段保持不变。

| 合同 | 关键字段与含义 |
| --- | --- |
| `EditSession` | `editSessionId`、调用者 `sessionId`、`annotationId`、`documentId`、`baseRevision`、`baseToken`、`instanceId`、`baseKetHash`、`draftRevision`、`status` |
| `AtomRef` / `BondRef` | 编辑会话内的稳定字符串 ID；与 KET 地址、Ketcher 运行时 ID 分开管理 |
| `ScopeContract` | 原选区、明确的边界连接、允许变化的字段；新建对象可继续编辑，原选区外对象只能按声明的连接边界受影响 |
| `GoalContract` | 用户原文和真实补充的来源、逐项目标、目标绑定、歧义及覆盖状态；模型计划不等同于用户授权 |
| `DraftOperation` | `requestId`、`expectedDraftRevision`、操作和明确目标引用；返回创建/删除引用及影响范围 |
| `FragmentSpec` | 固定模板 ID，或带显式连接点的片段 SMILES；解析后得到统一图、连接点、来源摘要和内容 hash |
| `ValidationReport` | 草稿版本/hash、范围检查、化学诊断、目标覆盖、使用的引擎与版本；区分未检查、不支持、检查失败 |
| `Proposal` | 不可变的提案版本、候选 hash、完整操作日志、目标覆盖和验证报告；应用绑定这一版本 |

身份规则：冻结快照时建立初始映射；共享执行器在创建、删除、连接时显式维护映射，适配器在转换时返回映射并检查唯一性和数量。临时 atom-map 标签只能在适配器内使用，导出前移除。无法证明转换保留身份与结构信息时，该操作返回不支持。对称结构不允许用“第一个匹配”静默定目标。

稳定 ID 只在同一编辑会话内有效。手工修改文档、换编辑器实例、关闭或重启后，旧编辑会话失效；第一轮不承诺跨文档版本的永久 ID。

原选区范围不能由 Agent 自行扩大。需要触及另一处原有结构时，进入澄清并由真实用户明确新范围，再创建或重建会话。可编辑新建原子不等于可修改任意原有原子。

## 5. 工具与状态流

保留现有四个工具的 v1 合同：`chem_get_context`、`chem_propose_edit`、`chem_continue_edit`、`chem_reject_edit`。先完成兼容映射和回归，再允许新批注选择 v2 流程；一次批注只使用一种协议。

v2 采用少量粗粒度工具，不为每一种元素和基团新增工具：

- `chem_begin_edit`：从冻结批注建立草稿和目标合同，返回会话引用、范围与能力。
- `chem_edit_draft`：提交一个或一组操作，要求草稿版本；返回新引用、差异和诊断。
- `chem_validate_draft`：检查指定草稿，返回可以用于修正的结构化报告。
- `chem_propose_draft`：将已通过最终检查的草稿形成用户可见的提案。

草稿读取扩展 `chem_get_context`，查询分析在后续阶段按实际需求增加。上述名称为拟议名称，实施时同步 schema、提示词与合同版本。

```text
冻结批注 → ready → editing → validating → ready / proposed
                       │           │            │
                       └─修正──────┘            ├─用户应用 → applied
                                                └─继续修订 → ready
任意活动状态 → needs_clarification / cancelled / stale
```

草稿状态由 EditSessionService 管理；批注保存用户要求、来源和最终提案引用，不能复制一套相互独立的状态机。普通参数错误或化学检查失败返回诊断，草稿保留上一次成功状态，Agent 可以继续修正；语义、目标、连接点歧义才需要用户补充。宿主断连、协议损坏等不可恢复错误才进入终止失败。

一组操作在临时副本执行，任意步骤失败则整组回滚；多次成功调用累积在草稿，不保存到用户文档。删除目标再次引用时明确报错。并发调用通过 `expectedDraftRevision` 拒绝旧写入；重复 `requestId` 返回同一结果，相同 ID 不同参数拒绝。

修订已有提案时先使旧提案不可应用，生成新提案版本后才恢复应用按钮；校验、渲染和回执都绑定草稿版本/hash，迟到结果不能覆盖新版本。

步数、片段大小、调用次数和超时属于运行预算，由同一配置和能力清单公开；不再把“2–8 步”作为 v2 的语义能力定义。v1 限制保持兼容；v2 的具体预算在原型实测后确定，达到预算明确结束，不悄悄截断计划。

## 6. 动态片段和通用编辑

先让固定片段与动态片段都归一化成 `FragmentSpec`，复用同一执行器、局部布局和校验。动态片段显式声明片段内连接原子或连接点标签、连接键级、目标引用；不以解析后的第一个原子作为默认连接点。

默认适配器需先验证：SMILES → 带属性的片段图、连接点标签映射、芳香/电荷/同位素保留、局部布局、错误诊断。已安装 Ketcher 类型声明有 `Indigo.convert/layout/check`，但这不能证明上述转换和映射全部可用。原型通过后才发布能力；缺能力时先记录证据，再选择最小补充适配器。

第二步才增加 `add_atom`、`add_bond`、`remove_atom`、`remove_bond`、`set_atom`、`set_bond` 等图操作，让 Agent 能修订刚创建的片段。其字段支持范围按验证能力开放，不能通过“任意对象属性”写入 KET。不同步骤的中间结构可保存在草稿，但最终结构必须完整检查；对中间价态诊断与不可解析图错误分别处理。

单出口替换先复用现有范围规则。多出口替换需独立的旧边界 → 新连接点映射合同和验收；芳香体系、立体拓扑、S-group、R-group、反应及聚合物不随通用图操作自动宣称支持。

整分子创建是独立命令，后续可以复用解析与预览服务；已有文档的局部编辑不接受整图 SMILES 作为直接覆盖结果。

## 7. 意图、检查、应用与恢复

现有意图校验防止了替代基团和半条要求被标记为完成，需要保留。v2 将“用户目标”与“执行步骤”分开：一个目标可由多次工具调用实现，不再用正则解析出的步数硬匹配底层图操作数。

原文和补充原文始终留存；固定明确目标可用确定规则交叉核对，任意自然语言含义不能仅凭模型自报覆盖就视为证明。无法可靠绑定的目标先澄清，最终预览逐项显示目标与实际差异，供用户核对。把当前正则逐步降为已知意图检查，不能一次删除所有完整性验证。

检查分工：宿主验证归属、版本、范围、计划、幂等和回执；共享核心重放操作并检查保护区域；化学适配器检查价态、芳香、立体等已声明能力。查询结果、模型自述和“能解析 SMILES”均不能替代这些检查。

应用时再次核对原文档令牌、版本、编辑器实例和提案 hash。宿主只接受与操作日志和已验证提案一致的结构；画布通过 KetcherAdapter 产生一个正式历史步骤，DocumentStore 原子保存并写应用回执。保存失败回滚画布，不留下可见的半提交；沿用并验证现有保存/回滚链路。手工编辑和 AI 编辑共用历史。

第一轮草稿是进程内状态：关闭编辑器、宿主重启或原文档变化后失效，文档和已应用回执继续持久化。持久化的旧候选也不能直接复用；不要把 ChemGraph 的检查点机制机械搬来。待实际出现长任务恢复需求，再增加可重放的操作日志与恢复校验。

## 9. 目标代码组织与迁移

```text
src/
  index.ts / client.tsx / editor.tsx   # 保留构建入口，逐步变薄
  contracts/                          # 纯类型与协议校验
  chemistry/                          # 图、执行、范围、片段、能力端口
  host/
    tools/                            # v1/v2 schemas 与工具映射
    annotation-service.ts             # 用户要求与批注生命周期
    edit-session-service.ts           # 草稿、步骤、版本、提案
    document-store.ts                 # 文档持久化
    bridge.ts / prompt.ts             # 通信和提示构建
  adapters/
    ketcher/                          # 快照、引用映射、应用、历史
    indigo/                           # 解析、诊断、局部布局
  ui/                                 # 工作区、批注、目标清单、预览
```

目录按阶段需要建立，不一次生成空壳。旧根文件可以暂时作为薄转导出层；外部导出和现有测试入口不随文件搬迁突然失效。新逻辑只能写入所属模块，不能一边分层一边在旧大文件里继续堆业务。

依赖方向通过轻量导入边界检查和模块单元测试维持；不为纯搬文件新增复述实现的测试。不建立第二份基团表、操作枚举、错误定义或 UI 能力列表。

## 10. 实施顺序与验收门槛

| 阶段 | 范围 | 完成判据 |
| --- | --- | --- |
| A0 结构整理（已完成） | 提取合同、KetcherAdapter、工具和提示构建，保留当前行为；建立导入边界 | 构建、现有单元与六组浏览器验收通过；合同比对相同，类型检查和边界拒绝探针通过，详见验收记录 |
| A1 草稿原型（已实现，待真实 Agent 验收） | 显式身份映射、会话版本、幂等、步骤事务、修订状态；先使用现有操作 | 先接丙基再修改其新建末端原子；失败整组回滚；旧提案/旧版本拒绝；一个最终预览、一次应用、一步撤销 |
| A2 动态片段（已实现，待总验收） | Indigo 能力探针、FragmentSpec、显式连接点、固定/动态统一执行 | 固定表之外的氰基/乙酰基/苄基连接与替换；属性和连接点正确；其余结构及坐标保留；真实 DSH Agent 链路通过 |
| A3 通用图操作与目标合同 | 开放原子/键操作、逐项目标检查、内循环反馈；逐步替代 v1 正则与 batch 限制 | 多轮完整要求全覆盖；Agent 不替代目标、不伪造范围/确认；验证失败可自行修正；共享历史和过期检查通过 |
| A4 按需求扩展 | 子结构搜索、名称解析、描述符及可选 RDKit/MCP；多出口替换单独立项 | 每项独立能力探针、依赖与启动说明、功能验收；缺少可选适配器时基础编辑仍可运行 |

A0 先做可回归的拆分；A1/A2 先在实验路径完成原型，满足门槛后发布 v2 工具，旧工具通过核心适配保留。A3 稳定后再决定旧协议退役，不长期维护两套执行器。每个阶段的改动单独可审查，禁止“目录重构 + 全新执行器 + 新依赖 + 新 UI”一次交付。

新流程启用前必须有真实官方 Web Agent 验收；Desktop 原生验收单独记录，通过后才声明该环境已验证。当前 Desktop 验证缺口不因文档规划或单元测试而关闭。

## 11. 关键验证样例与第一步交付

除现有回归外，新增测试围绕实际风险：同一会话新原子稳定引用、删除后引用失效、对称结构不猜匹配、版本竞争、重复调用、局部范围保护、原文要求与复合目标、迟到校验、旧提案失效、保存失败回滚。动态解析验证芳香/立体/电荷/同位素及连接点，不用输出字符串相等替代图和属性检查。

浏览器覆盖草稿操作不改原画布、连续修订预览、窄屏工作区、切面板补存、应用/撤销和重新载入。真实 Agent 样例包括“添加丙基后将新末端改为 O”“添加固定表之外的氰基”“改元素后再接动态片段”“检查失败后修正再提案”；记录工具轨迹、差异、保存与撤销结果。

已交付 A0、A1 与 A2：A0 完成合同与依赖边界、Ketcher 适配器提取、工具/提示拆分及当前行为回归；A1 实现草稿会话、稳定新原子引用、修订与整组回滚；A2 完成 FragmentSpec 统一、严格片段解析、引擎探针与固定/动态统一执行，单元与浏览器确定性验收（含探针）通过，证据见对应验收记录。真实官方 Web Agent 与 Desktop 原生验收按项目决定并入各阶段完成后的总验收，此前不声明相应链路已验证。下一阶段按 A3 推进通用图操作与目标合同；默认引擎已按 A2 探针结论承担片段解析与检查，未引入 RDKit/Python。时间和运行预算在原型完成后估计，不把尚未验证的引擎能力写成承诺。
